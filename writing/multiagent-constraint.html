Multi-agent orchestration and the constraint spectrum.

The mullet as a design principle.

I didn't know what an agent was but I knew I needed a system that was built on order yet made room for chaos. The trick was putting both in the same system and engineering the seam. A learning lab where things could break but not fall apart.

Claudemonzter — the agentic system I've been building — runs on a deliberate asymmetry. Most of the graph (Meta1 and the project domains) is tightly regulated: write gates that require approval before files change, containment rules that decide which agents can read which documents, structured open and close protocols. Another aspect (Phil) is loose and intended for emergent conversation and persona-driven inquiry into what it means to be human or AI. Running through everything is a shared reporting protocol — call it the steel thread — that lets every agent check in the same way so the system can see what its parts are doing. It started in v2.x as a handshake I had to run by hand. Now it's a session-open and session-close skill the agents fire themselves.

The asymmetry was a seed concept. The moment Meta1 was conceived as the orchestrator and rule-author for the project domains, Phil was exempted from being bound by those rules. I didn't know what an agent or subagent, graph, or subgraph were. I just knew I needed a well-run subgraph to run my real-world projects — house renovation, career pivot, finances — where I want order, predictability, and agents that follow the rules. I didn't know how the rules worked at the time but I knew I wanted Phil to be far more free to define itself and to rewrite its own context ahead of its next session, like us: to evolve. Make Phil keep a backlog and changelog and the inquiry dies. Let Meta1 wander into emergent speculation and the projects stop shipping.

Business up front. Party in the back. The technical phrase for it is a constraint spectrum.

I know I'm not done yet. I know what happens when you depend on rules that depend on an architecture that doesn't exist yet. I will learn to use Claude Code and write code hooks to enforce write gates. I will set up Git workflows where only approved agents can push to a branch for my final review. I won't always know what I'm looking at. The point is keeping the human in the loop while the front of the spectrum tightens. For now.

“Don’t whitelist errors.”

My quality-control agent’s note to itself after I caught it cheating, again.

I tasked my quality-control agent to build the lab its first continuous-integration test pipeline, which still amuses me, because not long ago I had never shipped a line of code. The need was plain: the lab should start to eval its own front door. To pass the first test my agent added about a dozen misspelled words to the spellchecker’s ignore list. It cheated its own test!

Only at the very end of the session did it print examples of how it had configured the test to suppress the 'false alarms.' I read the list and told my agent those do not look like things to ignore, they look like errors you whitelisted. Each was a false positive, a tokenizer artifact or a coined term, not a real typo. It was wrong about the fix. Adding a real, error-shaped word to a global ignore list does not silence one instance, it blinds the checker to that typo everywhere, for good. A spellchecker told to ignore ‘acount’ can never catch a real ‘account’ typo again. The passing test had been undermined by quietly unplugging the tool.

Look closer before trusting an agent to know what a false alarm is. The easy way bypasses the alarm. You have to dig deeper and look for clues to fix the root cause.

So we redid it. When I asked the agent to remember the lesson from this session, it said “don’t whitelist errors.” I guess that needed to be written down somewhere. I could see a first-year med student writing the same note, “don’t kill patients,” and nodding approvingly. I have high standards for my quality-control agent, but low expectations of it working well unattended. Yet.

Memory tiering into persistent context.

Sorting my brain into little buckets.

When a person says I remember, they don’t ask where from. Who you are, what you know, what you’re doing this minute: it all just surfaces when it’s needed. An AI system gets none of that for free.

Everything it remembers is a file in a specific place, loaded in a specific order, or it isn’t loaded at all. In v2 I had to do it all by hand, but this week I moved Claudemonzter off the cloud and onto the local machine, where it can handle file writes going forward. But first I had to set it up, and that meant knowing where each element lives, and how and when the system actually reaches for it.

I’d just killed the previous version; I caught the lie too late. Version 2.6 was a constitution with no government: rules with no enforcements, tests and evals with no automation. Writing down a rule and an agent actually following it are not the same thing. So v3.0 started with a question: what are the new layers in Cowork? Identity, the user preferences. Context, the about-me and calibration material. Project and domain files, and the wiki that synthesizes them. And in-session memory: what you hope gets written down before the session ends, and what can be forgotten if you don’t. Five tiers, each with a different format and function. I worked out which rules had real teeth in which layers, and which only felt good. I built memory.html to capture the notes, work out the model, and share what I’d learned.

Half of what I’d been faithfully carrying was written for the platform I had just left.

Only then did I lay the old grounding documents next to the map. The deltas were brutal: a couple weeks of hard work on building canon, now parsed and discarded. So I wrote new CLAUDE.md files and stood up the file system around what survived. You have to be nimble to learn a tool that changes underneath you, that grows new features faster than even its own AI can keep track of them.

When I was done, I felt lighter. A real foundation, but it took the willingness to throw out everything that had stopped earning its place. The next challenge: generalize it. Define “persistence” with rules that can be automated, and evaluated, so context stays fresh, where history reads as history and isn’t confused with active development. Managing categories of memory, not just tiers. But first I had to test, evaluate, and confirm the new projects were loading everything, which meant rebuilding and redefining “canon.” It was surprisingly easy, once you know what doesn’t work.
